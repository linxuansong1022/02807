## 1. 项目概述

### 问题

音乐平台每天都有新歌上线，存量曲库里也有大量只被少数人听过的长尾歌。基于行为的推荐（协同过滤）依赖收听记录，对零记录的新歌无能为力。工业界的常见做法是借助内容信息，把新歌"借道"相似老歌推送给潜在听众，网易云音乐的 I2I2U 冷启动方案就是一例（Zhao et al., 2023）。

本项目研究的是**物品冷启动**，任务视角是**给一首新歌找目标听众**：对所有用户打分，取前 K 位作为推送对象。

### 目标

搭建并评估一套可复现的新歌冷启动流程：在新歌没有任何收听记录时，仅凭内容信息（Last.fm 标签）找到真实听众；用消融实验说明各组件的贡献；并通过分析"内容相似度与听众相似度是否一致"，解释方法有效或无效的原因。

## 2. 研究问题

**RQ1（核心）**：对完全没有收听记录的新歌，结合"内容近邻 + 听众聚类"和"内容到协同映射"的推荐流程，能否比 baseline 更有效地找到真实听众？各组件分别贡献多少？

- **补充分析**：在老歌上，标签相似度与听众相似度的一致程度如何？是否因歌曲流行度而不同？
- **LSH 效率检验**：与精确 Jaccard 搜索相比，LSH 节省了多少计算时间，近邻质量和最终 Recall 损失多少？这一小节用来说明 LSH 是解法的必要部分，而不是可以省略的步骤。

**E1（扩展）**：新歌积累前 k 位听众时，融合内容与行为信号能否在各阶段都保持优势？最优权重如何随 k 变化？

**E2（扩展）**：数据规模增大时 LSH 的扩展性；加入音频特征是否有帮助；推荐结果在流派上的偏差。

## 3. 数据

### 3.1 数据集

[Music4All-Onion v2](https://zenodo.org/records/15394646)（Zenodo，2025 年发布，全部约 19.9GB）。所有文件都以**同一个歌曲 id** 为键，合并就是按 id 做 join。

### 3.2 需要下载的文件（共约 2.3GB）

| 文件 | 压缩大小 | 内容 | 用途 |
|---|---|---|---|
| `userid_trackid_timestamp.tsv.bz2` | 约 2.2GB | 每条收听记录：用户、歌曲、时间戳（119,140 用户，56,512 首歌，252,984,396 条） | 核心数据：时间切分、听众排序、播放次数 |
| `id_tags_dict.tsv.bz2` | 约 15MB | Last.fm 标签及权重 | 构建 MinHash 用的标签集合 |
| `id_tags_tf-idf.tsv.bz2` | 约 45MB | 加权标签的 tf-idf 向量 | 岭回归映射的输入特征 |
| `id_genres_tf-idf.tsv.bz2` | 约 3MB | 流派 tf-idf | 同流派 baseline、分组分析 |
| `README.md` | 20KB | 字段说明 | 参考 |
| （E2）`id_ivec256.tsv.bz2` 或 `id_musicnn.tsv.bz2` | 约 86MB / 24MB | 预提取的音频特征向量 | 音频扩展 |

### 3.3 不需要下载的文件

- **其余音频特征**（BLF、OpenSMILE、MFCC、jukebox、essentia 等）：都是预提取的特征向量，不是音频本身。基础版用不到。
- **视频特征**（`id_incp`、`id_resnet`、`id_vgg19`）：从 YouTube 音乐视频截帧得到的图像向量，不是封面图。用不到。
- **歌词相关文件**：用不到。
- **`userid_trackid_count.tsv.bz2`**：整个时间段的累计播放次数。直接用于训练会造成时间泄漏，所以播放次数一律从时间戳文件中按 T 之前的记录计算。

### 3.4 已知的数据问题

- **覆盖不一致**：收听记录只涉及 56,512 首歌，特征文件覆盖 109,269 首；标签和流派文件的覆盖数在 README 里没有给出。实验曲库 = 有收听记录 ∩ 有标签的歌，规模需要在第 0 步统计。
- **没有歌手信息**：所以 baseline 用同流派代替同歌手。
- **"新歌"的含义**：一首歌在日志里第一次出现，不一定是真正的新发行。不过对推荐系统来说，系统里没有记录的歌就是冷启动物品，所以定义是成立的。T 放得离数据起点远一些，可以让"首次出现 ≈ 新上线"更接近真实。报告里如实说明这一点。
- **处理速度**：2.5 亿行的 bz2 是单线程解压，很慢。只解压一次，用 polars 或 duckdb 转成 parquet，之后都读 parquet。抽样用户也在这一步完成。

### 3.5 时间切分与定义

- **时间点 T**：T 之前出现过的歌为**老歌**，用于训练所有模型（ALS、岭回归、LSH 索引、标准化等）。
- **新歌**：首次播放时间晚于 T，且 T 之后至少有约 20 位听众（**待确认**）。从中划出验证集（只用于调参）和测试集。
- **每首新歌的听众按首次收听时间排序**：
  - 前 10 位是"预热池"，只在 E1 里揭示前 k 位；
  - 第 10 位之后的听众是**评估目标** T_s，核心实验和 E1 用同一批目标，结果才可比。
  - 这个门槛会让样本偏向后来较受欢迎的新歌，报告里需要说明。
- **强信号**：数据没有收藏或红心，用"T 之前同一首歌播放 ≥2 次"代替（**待确认**）。
- **调参方式**：用时间划出的验证集新歌，不用随机 k 折交叉验证（会把未来信息混进训练）。如果需要检验稳定性，可以换几个 T 做滚动切分。

## 4. 方法

完整系统由两路内容打分组成，都只用标签，适用于零收听记录的新歌。

### 4.1 A 路：内容近邻 + 听众聚类（两个课程 topic）

**① 找相似老歌（MinHash LSH）**
- 标签集合：从 `id_tags_dict` 中取权重高于阈值的标签（阈值第 0 步看分布后定）。
- 对新歌和老歌的标签集合计算 MinHash 签名（如 128 个哈希），用 banding 找候选近邻，b、r 根据 S 曲线选择。
- 对候选计算精确 Jaccard，取前 N 首（如 50）作为近邻。
- 暴力精确 Jaccard 作为参照，用于效率检验。

**② 候选听众池**

$$\text{pool}(u) = \sum_{n \in N(s)} \text{sim}(s, n) \cdot r(u, n)$$

- r(u, n)：用户 u 在 T 之前对老歌 n 的强信号播放，比如 log(1 + 播放次数)。
- 取前 M 位用户（如 1000）作为候选池。因为是给同一首歌对用户排序，不需要除以相似度之和。

**③ 听众聚类定位（k-means，参考网易 CAT 的思路）**
- 用暖启动 ALS（只用 T 之前的数据训练）的用户向量，对候选池做 k-means，c = 3–5 个簇。
- 每个簇的权重 = 簇内用户的池分数之和。
- 对**所有用户**计算与簇中心的加权相似度：relevance(u) = max_c 权重_c · cos(u, μ_c)。
- A 路分数：

$$A(u) = \beta \cdot \widetilde{\text{pool}}(u) + (1-\beta) \cdot \widetilde{\text{relevance}}(u)$$

  波浪线表示归一化，β 在验证集上调。
- 作用：降噪（弱化"什么都听"的用户），扩展（找到没听过那几首相似老歌、但口味接近的用户）。

### 4.2 B 路：内容 → 协同向量映射（课外方法）

- 用老歌训练岭回归：输入是 tag tf-idf 特征 X，输出是暖启动 ALS 学到的歌曲向量 V。
- 对新歌：v̂_s = 映射(x_s)，B(u) = u · v̂_s。
- **流行度加权（可选，待确认是否放进核心）**：训练时样本权重取 1/log(1 + 收听数)，降低热门歌的主导作用，对应"热门学得多、冷门学得少"的问题（Zhao et al., 2023）。在消融表里作为一行对比。
- 正则化强度在验证集上调。

### 4.3 完整系统

$$\text{score}(u) = \gamma \cdot \widetilde{A}(u) + (1-\gamma) \cdot \widetilde{B}(u)$$

- 归一化：对每首歌做 z-score，或转成排名分位数（第 2 步时确定一种）。
- γ 在验证集上调。
- 对所有用户排序，前 K 位即推送对象。

### 4.4 扩展 E1：冷启动到长尾

- 揭示前 k 位听众，k ∈ {0, 1, 3, 5, 10}。
- **协同分数 C(u)**：用已揭示听众的用户向量解出新歌的 ALS 向量（fold-in），再与所有用户向量做内积。
- **融合**：

$$\text{score}(u) = w(k) \cdot \widetilde{C}(u) + \big(1-w(k)\big) \cdot \widetilde{\text{content}}(u), \quad w(k) = \frac{k}{k+c}$$

  - c 的含义：新歌积累到 c 位听众时，行为信号与内容信号同样可信。
  - c 没有通用取值，在验证集上网格搜索 {0.5, 1, 2, 5, 10, 20}。
  - 另外对每个 k 单独搜最优 w，与 k/(k+c) 曲线对比。

## 5. 评估

### 5.1 指标（从新歌的视角计算，对所有测试新歌取平均）

- **主指标**：Recall@K = |前 K 位用户 ∩ T_s| / min(K, |T_s|)。K 暂定 100，另报告 50 和 200（**待确认**）。
- **NDCG@K**：真实听众是否排在前面。
- **推送集中度**：所有新歌的前 K 位推送中，落在最活跃 10% 用户身上的比例。用来检验方法是否只是在"推给重度用户"。
- **分组报告**：按新歌最终流行程度、按流派。

### 5.2 Baseline

| Baseline | 含义 |
|---|---|
| 随机用户 | 下限 |
| 最活跃用户 | 推给 T 之前听歌最多的用户。在"给歌找人"的设定下很强 |
| 同流派重度听众 | 推给 T 之前听该流派最多的用户（替代同歌手） |

### 5.3 消融实验（k = 0）

| 变体 | LSH 候选池 | 听众聚类 | 协同映射 | 检验什么 |
|---|---|---|---|---|
| 完整系统 | ✓ | ✓ | ✓ | 整体效果 |
| 去掉聚类 | ✓ | | ✓ | 听众聚类的贡献 |
| 仅 A 路 | ✓ | ✓ | | 映射的贡献 |
| 仅 B 路 | | | ✓ | 近邻路线的贡献 |
| 仅候选池 | ✓ | | | 最简单的内容近邻方法 |
| （可选）映射无流行度加权 | ✓ | ✓ | ✓（无加权） | 流行度加权的作用 |

### 5.4 LSH 效率检验（并入 RQ1）

- 精确 Jaccard 与 LSH 的索引构建时间、查询时间、内存；
- 近邻重合率：LSH 找到的前 N 位近邻中有多少是真实的前 N 位；
- 分别用两种近邻时，完整系统的 Recall@K 差多少。

### 5.5 解释性分析

- 在老歌中抽样歌曲对，计算标签 Jaccard 和听众集合 Jaccard（只用 T 之前的听众）；
- 报告 Spearman 相关系数和散点图，并按流行度分组。
